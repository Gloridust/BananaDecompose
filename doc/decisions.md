# 设计决策

记录每个取舍的**理由**，以及被推翻过的做法。代码能说清"是什么"，这份文档说清"为什么"和"为什么不"。

---

## 每个 API 路由只做一次模型调用

多步编排全部在浏览器里。

**为什么**：Vercel Hobby 的函数上限是 60s。一次七组扫描要几分钟，塞进一个函数必挂。拆成细粒度路由 + 客户端编排后，没有任何函数逼近上限，也不需要队列或后端状态。

**代价**：所有像素运算必须在浏览器 canvas 上跑。反过来这也成了优点 —— 抠图和字形测量的中间结果在 devtools 里直接可查。

---

## 砍掉「原生透明」

**为什么**：Gemini 系图像模型全都不输出 alpha。`background: transparent` 参数存在，但对这个模型族必然失败。

留一个必然失败的选项只会浪费用户的钱。删掉，而不是留着当"对照组"。

---

## 背景重建没有开关

曾经是个 toggle，现在强制执行。

**为什么**：底板上还留着已经被抬走的东西，那不是分层文件，只是一张图上面浮着它自己的副本。这个开关只是在"能用"和"不能用"之间选，不是取舍。

连带删掉了两条会产出脏背景的评测分支（`掩码关` / `全关`）。它们展示的不是取舍，是不可用。

**同时修的**：擦除区域曾经绑死在量出的墨迹上，所以关掉字形贴合就等于关掉了文字擦除。现在没量到墨迹就退回模型的粗框 —— 擦大一点无所谓，那块反正要重建；漏擦一段就等于在图层底下留了一个自己的副本。

---

## 几何从像素量，不从模型要

见[文字回收](./text-recovery.md)。

**为什么**：Gemini 的 `box_2d` 官方定位就是粗检测，`fontSize` 是猜的。Google 自己精确几何用 Cloud Vision。本项目坚持纯 Gemini，所以把职责拆开：模型说这是什么字、像什么字体；像素说它在哪、多大、什么颜色。

**被推翻过的做法**：用字距强行把宽度拉齐来对齐。它确实能让墨迹框重合，但**把字体最强的区分信号（自然宽度）抹掉了** —— 字体回测 0/3。改成先按高度缩放、让宽度自由分歧后 3/3。

---

## 掩码一次只问一个对象

**为什么**：批量请求实测 >170s 才超时。掩码是以 base64 文本形式混在补全流里返回的，多个对象叠起来就是几万 token 的纯文本输出。

现在每次只问一个，输入图降到 768px，45s 超时后干净降级成矩形裁切。

---

## 擦除失败要降级，不要炸掉分支

**为什么**：Gemini 的版权过滤器会拒绝对含艺术字的图片做"移除文字"，返回 `flagged for copyrighted or trademarked material`。这在实跑里出现得够频繁，当作致命错误会白白扔掉一条其余都完成了的分支。

提示词已经改成「把表面恢复成空白状态」这类修复式表述来降低触发率。仍被拒时降级为沿用原图，节点标黄。

---

## 同管线的分支共享上游

**为什么**：不这么做的话，所谓"评测"就只是 N 次互不相干的生成摆在一起，差异里混着模型的随机性，什么也说明不了。

共享上游顺带把一次七组扫描的出图次数从 32 降到 30。

**作用域是轮次不是画布** —— 否则第二轮就没法用新的提示词。

---

## 节流是全局的，不是每条分支各限一份

**为什么**：按分支限流的话，分支数量会乘进请求量，所以分支只能串行跑。全局池让所有分支同时开跑而总在飞数不变 —— **调度器决定负载，拓扑不决定**。

---

## 指标不适用时报 `—`，不硬凑数字

- **重建 PSNR/L1** 需要一张原图做参照，只有拆解管线有
- **底色残留** 需要一个彩色键，双渲染没有单一键色

硬凑一个数出来只会让人比错东西。

---

## 保留原始笔画是拆解的默认

**为什么**：AI 画的中文书法、手写体、艺术字，**没有任何 web 字体能还原**。字体回测挑出来的"最像的"依然是另一只手。

保留原始笔画像素级一致，代价是改字要重绘（2 次调用）。这在多数场景下是更好的默认 —— 大部分时候你不改字，只想调位置和层级。

附带的好处：**它对擦除失败免疫**。抠出的原字正好落回它自己的位置，就算背景没擦干净也不会重影。

（正因如此，用来展示"地板"的那条评测分支被钉死为「重排为真文本」—— 否则它想展示的失败会被掩盖。）

---

## 历史索引和节点数据分开存

localStorage 存索引，IndexedDB 存节点数据。

**为什么**：节点图像是 data URI，localStorage 那 ~5MB 配额大概只装得下两张生成图，而这个 demo 的意义就是攒很多张画布来对比。索引留在 localStorage 是为了列表秒开、devtools 里可读。

**被推翻过的做法**：设置用顶层浅合并。存过的 `decompose` 块会整块替换掉默认块，后加的选项全变成 `undefined` —— 静默关闭，而 UI 还把这个过时形状显示得像是主动选的。现在下沉一层合并。

---

## 圈选重绘落成图层，不拍进底板

**为什么**：在分层文件里，一个关不掉也移不动的编辑不叫编辑，叫提交。补丁作为独立图层叠上去，就能隐藏、移动、删除、调层序 —— 跟其他图层一视同仁。

裁片外扩 18% 带上周边，是因为模型看不到邻域就接不上光照和风格，回来的东西像贴纸。边缘 smoothstep 羽化，是因为重画结果不透明到边，直接贴会留一个可见矩形。

## 没做的事

| | 为什么不做 |
|---|---|
| **本地 GPU 分层模型** | [Qwen-Image-Layered](https://github.com/QwenLM/Qwen-Image-Layered)（Apache 2.0）是目前最强的开源拆解方案，但 1024px 约 120s、峰值 45GB 显存。这是纯 API 项目 |
| **专用 OCR** | Cloud Vision 的 `DOCUMENT_TEXT_DETECTION` 返回逐字符 vertices，定位精度上限高一个档次，但破了"纯 Gemini"的定位 |
| **真正的字体识别** | Adobe 背后是 3 万+ Adobe Fonts 的检索。渲染回测是弱识别器，所以它会在分差不足时认怂 |
| **带掩码的真局部重绘** | `erase` 和圈选重绘都是"整帧重画 + 按区域合成"，不是把掩码交给模型让它只动掩码内。生产环境应该用支持 inpainting mask 的接口 |
| **深度估计** | z-order 靠模型推断，没有 Depth Anything 一类的兜底 |
