# 两条管线

## A · 生成即分层（`lib/pipeline/compose.ts`）

不拆解 —— **从一开始就不拍平**。

```
提示词
  └→ 规划 Scene JSON            [1 次文本调用] 共享
       ├→ 背景板                [1 次出图]     共享（文字不入像素时）
       └→ 每个元素独立渲染      [1~2 次出图/元素]
            └→ 本地抠图
                 └→ 成品场景
```

### 1. 规划

文本模型产出结构化的 `ScenePlan`：背景提示词、元素列表（每个带**独立成句的出图提示词**和 0..1000 的位置框）、文案列表（内容、位置、颜色、字体、字号、对齐）。

提示词里有两条硬约束：

- 每个元素的提示词必须**能脱离上下文单独渲染** —— 渲染器只看得到这一个字符串
- **画面里不许出现任何文字**。需要文字的地方就画空的容器或留白

### 2. 背景板

只画背景，没有主体、没有文字。所有「文字不入像素」的分支共享同一张 —— 抠图策略不影响背景，各自重画只是多花钱。

### 3. 元素

每个元素单独渲染在**已知的纯色底**上，再本地算出 alpha。四种策略见[抠图](./matting.md)。

抠完的主体按规划的框做等比 contain 放置，不拉伸。

### 4. 文字

两种策略：

- **文字不入像素**（默认）：直接用规划里的文案建文本节点。**从未进入像素**，所以零损耗
- **烘焙后回收**（对照组）：让模型把文案画进背景，再走完整的 OCR → 字形贴合 → 擦除重建。用来量化「事后回收文字」到底掉多少精度

### 为什么 A 的构图偏简单

规划模型只能想出它能用语言描述清楚的构图，而每个元素还必须能孤立渲染 —— 这排除了元素之间的遮挡、交互、共享光影。实测下来画面丰富度明显不如让图像模型一次画完。

**这是这条路线的固有代价，不是实现问题。**

## B · 事后拆解（`lib/pipeline/decompose.ts`）

先出成品，再拆回图层。形状上是 [ReDesign](https://arxiv.org/html/2607.25565) 那套，去掉本地 GPU。

```
提示词（或上传图）
  └→ 来源平图                    [1 次出图] 共享
       └→ 读版面                 [1 次视觉]
            ├→ 回收文字          [每段 1 次视觉]
            ├→ 分割掩码          [每个元素 1 次视觉]
            └→ 擦除重建          [1 次出图]
                 └→ 按区域合成 → 切元素 → 成品场景
```

### 顺序为什么是这个

**先量文字，再擦除，最后切元素。** 三步顺序都不能换：

1. 墨迹必须在**还带着文字的像素**上量
2. 擦除后先合成出「去文字图」
3. 元素从**去文字图**上切 —— 这样抬起一个元素时不可能把烘焙的文字一起带到干净底板上

第 3 步是之前双影的直接来源：元素原本从原图上切，无掩码时是矩形，矩形里裹着原文字，贴回干净底板再盖上文字层 = 双影。

### 按区域合成

`erase` 是整图重绘，输出会全局漂移。所以只在**真正抬走东西的地方**采用重绘像素：

```
去文字图 = 原图     × (1−文字掩码) + 重绘图 × 文字掩码
背景板   = 去文字图 × (1−元素掩码) + 重绘图 × 元素掩码
```

其余像素与原图逐位一致。掩码边缘做了羽化，接缝不可见。

### 擦除区域永远存在

量到墨迹就用精确框，没量到就退回模型给的粗框。擦大一点无所谓 —— 那块反正要重建；**漏擦一段就等于在图层底下留了一个自己的副本**。

### 没有掩码的元素不生成图层

留在背景里。往干净底板上贴一个带原文字的矩形是纯负收益。所以「关掉掩码」的结果是**没有可编辑元素**，这就是那个开关的真实代价。

### 精度上限

学术界报的数字是 PSNR 约 26 / LPIPS 约 0.09。**视觉可用，但不是像素级还原。**
本项目的重建 PSNR / L1 会自动测出来，见[界面](./ui.md#量化指标)。

## 共享上游

同管线的各分支共享上游产物：

| 产物 | 共享范围 |
|---|---|
| 规划 Scene JSON | 一轮内所有 A 分支 |
| 背景板 | 一轮内所有「文字不入像素」的 A 分支 |
| 来源平图 | 一轮内所有 B 分支 |

烘焙文字的那条 A 分支自己重新生成背景 —— 它的背景里必须有字。

**不这么做的话，所谓"评测"就只是七次互不相干的生成摆在一起**，差异里混着模型的随机性，什么也说明不了。共享上游顺带把一次七组扫描的出图次数从 32 降到 30。
