# 抠图：Gemini 不输出 alpha

## 硬约束

Nano Banana / Pro / 2 —— **Gemini 系图像模型全都只输出不带 alpha 通道的 RGB**。要求"透明背景"，拿到的是纯白、纯黑，或者画上去的马赛克格子。

所以透明必须**算出来**。三种策略，全部在浏览器 canvas 上跑（`lib/matte.ts`），服务端不碰图像数据。

## 三种策略

### 双渲染差值（默认）

同一元素分别在白底和黑底各生成一次：

```
白底：Cw = F + (1 − α)      （F 为预乘前景）
黑底：Cb = F
  ⇒   α = 1 − (Cw − Cb)     颜色 = Cb / α
```

逐通道求 alpha 后取均值（两次生成不是像素级一致，取均值抵消漂移），极值处做吸附。

**成本 2×，精度最高。** 软边和半透明都能正确还原。

### 色键抠图

在纯品红底上生成一次，按色距抠除，并做去色溢（品红底的破绽是红蓝通道跑在绿通道前面）。

**成本 1×**，软边会留明显色溢。

### VLM 分割掩码

灰底生成一次，再向 Gemini 要 segmentation mask。掩码是 box 局部坐标的 base64 PNG，按概率场做软 alpha。

**成本 1× + 1 次视觉调用**，取决于 grounding 质量，拿不到掩码时降级为矩形裁切。

### 为什么没有「原生透明」

`/api/v1/images` 有 `background: transparent` 参数，但 Gemini 系不支持。留一个必然失败的选项只会浪费用户的钱，所以删掉了。

## 自检实测

`/selftest` 用**已知 alpha 的合成图**验证，不消耗 API。真值是带羽化边缘的橙色圆盘 + 45% 半透明的蓝色横条 —— 专挑软边和半透明两种最难还原的情况。

| 策略 | 平均 alpha 误差 | 最大 alpha 误差 | 平均颜色误差 |
|---|---|---|---|
| **双渲染差值** | **0.10%** | 5.88% | 0.08% |
| 色键抠图 | 4.17% | 35.29% | 0.91% |

> **这是算法上限。** 自检里两张底片像素级一致，真实模型两次生成会有漂移，实际误差更大。

色键的恢复结果上肉眼可见羽化边缘留了一圈品红 —— 那就是 4.17% 的样子。

## 自动裁边

抠完会裁掉完全透明的边距，让图层的框紧贴主体。带真 alpha 的源（掩码切出的）也走同一条路径。
